# ADR-0001：使用 JSON Schema 作为扩展与本地 Agent 的共享契约

- 状态：Accepted
- 日期：2026-09-02
- 关联文档：`docs/architecture/ui-and-module-boundaries-v0.1.md`
- 关联实现：`packages/contracts/v0.1/contracts.schema.json`

## 背景

浏览器扩展和本地 Agent 预计使用不同语言和运行时。首版需要先稳定字段语义、确认状态、
填写动作和隐私边界，同时保留 loopback HTTP/JSON 与 Native Messaging 的选择空间。只
依赖某一种语言的类型定义，会让另一端产生无法自动校验的隐含约定。

## 决策

采用 JSON Schema Draft 2020-12 作为跨模块契约，并以单一主文件
`packages/contracts/v0.1/contracts.schema.json` 作为事实来源：

1. 公共类型和消息放在主文件的 `$defs` 中，消息通过 `$ref` 复用；
2. 顶层 `oneOf` 列出全部公开消息，消费者既可直接校验消息，也可按定义名校验；
3. 示例和 Python 回归测试与 Schema 一起版本化；
4. Schema 固定安全不变量，例如不允许提交动作、敏感候选必须确认、远程发送必须记录
   用户同意；
5. 传输、前端/后端框架和代码生成工具不由本 ADR 锁定。

## 考虑过的替代方案

- **只共享 TypeScript/Python 类型**：无法让跨语言运行时直接验证，且容易出现字段漂移。
- **OpenAPI**：适合已确定的 HTTP 服务，但当前传输方式尚未决定，且页面动作消息并非
  典型资源 API。
- **Protobuf/gRPC**：类型和演进能力强，但首版需要额外的编译链和本地浏览器通信适配，
  不利于快速验证和开源使用。

## 影响

- 扩展和 Agent 可以在不同语言中实现，并共享同一份可读、可测试的字段约束；
- 严格对象和显式确认字段会增加早期实现的样板代码，但能把安全边界前移到运行时校验；
- 将来若需要代码生成或高吞吐传输，可以从同一语义模型生成新表示，但必须保持安全语义
  和版本兼容规则不变，并通过新的 ADR 记录迁移。

## 约束与后续

真实个人资料、API Key、网站配置和未脱敏文档不能进入 Schema 示例或 Git。新增跨边界
能力（例如长文本生成、复杂控件或网站配置 CRUD）应在对应 Feature 的规格冻结后，再以
向后兼容的可选字段或新主版本契约加入。
