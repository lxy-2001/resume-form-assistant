# 智能简历填写助手：首版产品边界与规格基线

- 更新日期：2026-09-02
- 状态：讨论基线，待最终签字冻结
- 上游文档：`docs/discussions/2026-09-01-smart-resume-form-agent-discussion.md`

本文将此前讨论过的产品方向、首版范围和验收标准集中记录，作为后续 Roadmap、Constitution 和各个 Feature 规格的共同依据。实现细节（具体框架、提示词、数据库表结构、DOM 算法和 OCR 库）不在本文中提前锁死。

## 1. 产品定义

### 1.1 一句话承诺

用户主动在求职申请页面启动助手后，助手读取本地资料，识别当前页面中的常见表单字段，尽量自动填写；无法确定的内容必须提示用户；所有重要操作可审核、可修改、可撤销，且永远不会自动提交申请。

### 1.2 产品定位

这是一个“确定性表单工具 + 受控 Agent 能力”，不是聊天型 Agent 产品。

- 浏览器插件负责读取页面、展示结果、执行受控填写和撤销。
- 本地编排服务负责资料处理、规则校验、模型调用和当前任务状态。
- Agent 只在需要语义理解、归类、候选生成或审校时被调用。
- 简单且明确的字段优先由规则和本地映射处理，不要求每个字段都经过模型。
- Agent 不具备任意浏览器操作权限，不自动提交，不进行验证码或反爬绕过。
- 不做长期对话、自动训练或不可见的“自主记忆”。用户确认后的映射如需保存，只作为可查看、可删除的普通本地配置。

## 2. 核心用户流程

### 2.1 资料进入资料库

支持两种入口：

1. 用户手动录入、编辑和删除字段；
2. 导入 PDF、Word 或文本文件。图像型 PDF 对页面进行 OCR，再进入同一套解析流程。

解析流程：

```text
文件/图片
  → 文字与版面提取
  → Agent 按标准字段归类和归一化
  → 类型、格式、枚举和一致性校验
  → 展示来源、置信度和疑问
  → 用户确认或纠正
  → 写入资料库
```

Agent 输出的是结构化候选结果，不直接改写程序规则。简单字段使用确定性规则校验；复杂语义由 Agent 辅助，最终以用户确认结果为准。

### 2.2 网页填写

1. 用户在当前网页主动点击“识别/填写”；
2. 插件读取当前页面可访问的表单信息；
3. 规则、本地资料和必要的 Agent 共同给出匹配结果；
4. 高置信度、非敏感且为空的字段可以自动填写；
5. 中低置信度字段进入待确认列表，不得静默填写；
6. 已有内容默认不覆盖，发生冲突时展示网页值和建议值；
7. 用户查看、修改、接受或跳过结果；
8. 系统执行本页审校，用户确认后自行点击下一步；
9. 进入下一步后重新识别，不由助手自动点击下一步或最终提交。

### 2.3 未知字段和自定义字段

当页面字段无法映射到现有字段时：

```text
识别未知字段
  → Agent 解释字段含义并给出候选
  → 用户填写、选择已有字段或创建自定义字段
  → 用户确认本次使用
  → 可选：保存为全局资料、网站配置或仅本次答案
```

Agent 可以提出新字段和校验建议，但未经用户确认不得永久新增或修改。

## 3. 资料字段模型

“标准字段”表示系统预置的语义集合，不表示每个网站或每个用户都必须填写。标准字段和自定义字段可以并存。

资料按使用范围区分为：

1. **个人资料**：稳定的个人信息、教育和经历；
2. **自定义资料**：用户主动增加的字段；
3. **申请答案**：只对某次申请有效的答案，例如期望薪资或是否接受出差；
4. **网站配置**：用户主动确认后保存的标签映射、格式转换或选择项对应关系。它是普通配置，不是 Agent 的长期记忆。

## 4. 首版标准字段清单

### 4.1 个人身份与联系方式

| 字段标识 | 中文名称 | 类型 | 默认处理 |
| --- | --- | --- | --- |
| `person.full_name` | 姓名 | 文本 | 普通字段，可自动填写 |
| `person.name_en` | 英文名/拼音名 | 文本 | 普通字段 |
| `person.gender` | 性别 | 枚举 | 普通字段 |
| `person.birth_date` | 出生日期 | 日期 | 普通字段 |
| `person.birth_year` | 出生年份 | 数字/年份 | 普通字段 |
| `person.birth_place` | 出生地 | 文本 | 普通字段 |
| `person.nationality` | 国籍 | 枚举/文本 | 普通字段 |
| `person.ethnicity` | 民族 | 枚举/文本 | 普通字段 |
| `person.id_number` | 身份证/证件号码 | 文本 | 默认必须确认 |
| `person.political_status` | 政治面貌 | 枚举/文本 | 默认必须确认 |
| `person.military_service` | 服役情况 | 枚举/文本 | 默认必须确认 |
| `person.marital_status` | 婚姻状况 | 枚举/文本 | 默认必须确认 |
| `contact.phone` | 手机号 | 电话 | 可自动填写，格式校验 |
| `contact.email` | 邮箱 | 邮箱 | 可自动填写，格式校验 |
| `contact.address` | 当前住址 | 文本 | 普通字段 |
| `contact.hukou_location` | 户籍所在地 | 文本 | 默认必须确认 |
| `contact.postal_code` | 邮政编码 | 文本 | 格式校验 |

### 4.2 教育经历（可重复）

每条教育记录包含：

- `education.school_name`：院校/培养单位；
- `education.college`：学院/系；
- `education.major`：专业；
- `education.degree`：学历/学位；
- `education.education_type`：全日制、非全日制等；
- `education.start_date`：入学时间；
- `education.graduation_date`：毕业时间；
- `education.gpa`：绩点；
- `education.rank`：排名或排名比例；
- `education.student_status`：在读/毕业等状态。

### 4.3 工作、实习和项目经历（均可重复）

每条记录包含：

- `experience.organization`：公司、单位或组织；
- `experience.title`：职位/角色；
- `experience.start_date`、`experience.end_date`：起止时间；
- `experience.description`：职责描述；
- `experience.achievements`：成果和量化结果；
- `experience.location`：地点；
- `experience.is_current`：是否正在进行。

记录类型区分为 `work`、`internship` 和 `project`。首版允许资料库保存这些结构，网页中的复杂重复控件按首版控件范围逐步支持。

### 4.4 能力、成果和链接

- `skills.general`：通用技能；
- `skills.technical`：技术技能；
- `skills.programming_languages`：编程语言；
- `languages.spoken`：语言能力及等级；
- `certifications`：证书；
- `awards`：奖项和荣誉；
- `research.publications`：论文、研究或公开成果；
- `links.github`：GitHub；
- `links.portfolio`：作品集；
- `links.linkedin`：LinkedIn；
- `links.other`：其他链接。

### 4.5 常见申请答案

这些字段默认属于“申请答案”，不自动视为永久个人资料：

- `application.expected_salary`：期望薪资；
- `application.preferred_location`：意向工作地点；
- `application.available_start_date`：可入职时间；
- `application.willing_to_relocate`：是否接受异地/搬迁；
- `application.willing_to_travel`：是否接受出差；
- `application.referral_source`：获知渠道；
- `application.other_answer`：其他问题的用户答案。

### 4.6 自定义字段

自定义字段至少包含：

- 用户可读名称；
- 字段类型（文本、日期、数字、布尔、枚举或多值）；
- 一个或多个值；
- 使用范围（全局、网站、本次申请）；
- 可选的敏感级别和校验限制。

首版支持简单自定义字段，不承诺用户可以直接定义任意复杂控件或任意网页脚本。

## 5. 产品范围表

| 能力 | 首版包含 | 首版不包含/后置 |
| --- | --- | --- |
| 资料录入 | 手动录入、编辑、删除、JSON/结构化导入 | 多人协作编辑 |
| 文档解析 | PDF、Word、文本、图像型 PDF OCR | 更复杂的版式恢复、批量云端解析 |
| 解析标准化 | Agent 归类、格式校验、用户纠正、来源和置信度展示 | 无人审核的永久写入 |
| 字段体系 | 系统标准字段 + 简单自定义字段 | 任意复杂字段设计器 |
| 页面识别 | 当前页面、当前步骤、可访问的常见 DOM 表单 | 保证所有网站和所有自定义组件 |
| 控件 | 常见文本框、文本域、下拉、单选、多选、日期等标准控件 | 复杂自定义控件、富文本、特殊画布控件 |
| 自动填写 | 规则优先，Agent 兜底；高置信度字段自动填写 | 无依据的猜测填写 |
| 已有内容 | 默认不覆盖，冲突时让用户选择 | 静默覆盖 |
| 多步骤表单 | 用户点击下一步后重新识别 | 自动点击下一步或跨页执行 |
| 长文本 | 用户主动开启、生成前后可审核 | 未经同意自动生成或替换 |
| 审校 | 必填、格式、置信度、明显冲突和风险提示 | 首版不做完全自动纠错 |
| 模型 | DeepSeek 的 OpenAI-compatible 接口；预留通用适配 | 首版不接大量原生厂商 SDK |
| 隐私 | 本地优先、远程调用需同意、API Key 本地保存 | 默认上传完整资料或默认遥测 |
| 网站适配 | 当前会话纠正；用户主动保存的本地映射可预留 | Agent 自主长期学习、自动共享规则 |
| 提交行为 | 只填写和审校 | 自动提交、批量投递、验证码/OTP/签名绕过 |
| 高风险信息 | 系统默认必须确认，用户可在设置中调整 | 默认无确认地填写密码、支付、证件等信息 |
| 部署 | 个人本地运行；Chrome/Edge 首版目标 | 多用户云端账户和共享适配市场 |

## 6. 首版验收标准

### 6.1 资料库和解析

- **AC-01**：用户可以手动新增、编辑、删除标准字段和自定义字段。
- **AC-02**：系统可以导入 PDF、Word 和文本文件；图像型 PDF 可以进入 OCR 流程。
- **AC-03**：解析结果在写入资料库前必须展示候选值、来源位置、置信度和疑问。
- **AC-04**：用户可以逐项纠正解析结果；纠正后的值成为最终资料，不会被后台自动改回。
- **AC-05**：简单字段经过类型/格式/枚举等规则校验；不符合规则的结果必须提示。
- **AC-06**：Agent 建议新增字段或限制时，未经用户确认不得永久生效。

### 6.2 页面识别和填写

- **AC-07**：用户主动启动后，系统能列出当前页面识别到的字段及其状态。
- **AC-08**：高置信度、非敏感且为空的标准字段可以自动填写。
- **AC-09**：不确定字段不能静默填写，必须进入待确认、跳过或人工接管状态。
- **AC-10**：用户能看到每个建议值来自哪个资料字段，以及采用该值的主要原因。
- **AC-11**：网页已有内容默认不覆盖；如建议值不同，必须先展示冲突并取得确认。
- **AC-12**：用户可以接受、修改、跳过单个字段，也可以取消本次填写。
- **AC-13**：每次填写都可以整体撤销，撤销后页面恢复到填写前状态（在网页仍允许恢复的范围内）。
- **AC-14**：多步骤表单中，助手不会自动点击下一步；用户进入下一步后可以重新识别。
- **AC-15**：不支持的组件或字段必须显式列出并给出人工处理入口。

### 6.3 文本、审校和安全

- **AC-16**：生成长文本前必须有明确的用户同意；插入前可预览和编辑。
- **AC-17**：审校功能可以提示缺失必填项、格式错误、低置信度和明显冲突，并给出修改建议。
- **AC-18**：审校建议不会未经用户确认自动修改高风险或已有内容。
- **AC-19**：没有用户同意时，任何资料不得发送给远程模型；发送时尽量只发送当前所需内容。
- **AC-20**：模型不可用时，规则能够继续处理简单字段，并向用户说明复杂字段无法判断。
- **AC-21**：系统永远不会自动提交申请，也不处理验证码、OTP、签名、支付和密码等高风险操作。
- **AC-22**：用户可以查看、删除和导出本地保存的资料与网站配置。

### 6.4 验收样例

至少使用以下场景进行端到端验证：

1. 空白的标准 HTML 申请表；
2. 部分字段已经填写的申请表；
3. 同义但不完全相同的字段标签；
4. 含中文文字层的 PDF/Word；
5. 图像型 PDF；
6. Agent 无法确定或模型接口不可用；
7. 含敏感字段和长文本字段；
8. 含不支持的自定义控件。

## 7. 后续扩展方向（不阻塞首版）

- 复杂自定义控件、附件上传、富文本和特殊日期选择器；
- 更多浏览器和移动端；
- 多份简历/多套资料版本；
- 用户主动维护的网站适配器和脱敏规则共享；
- 更强的跨字段语义审校和纠错；
- 多用户服务器部署、账户和同步；
- 更多模型的原生适配。
