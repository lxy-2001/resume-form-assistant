本文是项目的总体路线和进度记录。它记录里程碑、Feature 顺序、依赖、完成条件和当前状态；具体需求、技术方案和开发任务仍分别放在对应 Feature 的 `spec.md`、`plan.md` 和 `tasks.md` 中。

## 状态定义

```text
Planned → Specifying → Implementing → Reviewing → Done
                                      ↘ Blocked
```

- **Planned**：已规划，尚未开始；
- **Specifying**：正在编写或澄清 Feature 规格；
- **Implementing**：已建分支，正在开发；
- **Reviewing**：已完成开发，正在测试或 Pull Request 审阅；
- **Done**：验收、检查和合并均已完成；
- **Blocked**：需要外部信息、权限或产品决策才能继续。

### M1 本地资料库与资料解析

**目标**：用户能够可靠地建立、修正和管理自己的标准化资料。

**完成条件**：资料可手动维护；PDF、Word 和图像型 PDF OCR 解析结果可审核、纠正并保存；标准字段和自定义字段契约可供后续填写功能使用。

| Feature | 状态 | 依赖 | 交付物 |
| --- | --- | --- | --- |
| F001 本地资料库：手动录入与编辑 | Planned | F000A | 本地资料、字段类型、加密存储和基础测试 |
| F002 文档解析：PDF/Word/OCR | Planned | F001 | 原文提取、OCR、来源、置信度和待确认结果 |
| F003 资料标准化与人工纠正 | Planned | F002 | Agent 归类、规则校验、合并和纠正流程 |

### M2 浏览器页面识别

**目标**：插件能够读取当前页面当前步骤中的常见标准表单。

**完成条件**：扩展与本地服务可以安全通信；页面字段能被列出并映射到共享标准字段；无法识别的字段会显式报告。

**目标**：在用户可控的前提下完成常见字段的自动填写。

**完成条件**：高置信度字段可填写；不确定字段不静默操作；已有值不被无确认覆盖；整次操作可审阅和撤销；不会自动提交。

| F009 填写确认、冲突提示与撤销 | Planned | F007、F008 | 预览、修改、已有值保护和整次撤销 |

## 变更规则

- Roadmap 只记录项目级顺序和状态，不复制 Feature 的详细任务；
- Feature 状态在创建规格、开始开发、进入审阅、合并完成时更新；
- 产品范围变化先更新产品基线和 Roadmap，再修改受影响的 Feature；
- 里程碑只有在其子 Feature 全部验收并合并后才标记为 Done；
- 每次更新 Roadmap 都记录日期和当前重点；
- GitHub Project、Issue 和 Pull Request 可作为执行层记录，但不能替代仓库中的 Roadmap。
