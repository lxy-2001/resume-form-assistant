# Feature Specification: 本地简历资料库

**Feature Branch**: `feat/F001-profile-library`

**Created**: 2026-09-02

**Status**: Ready for implementation

**Input**: User description: “建立一个本地优先的简历资料库，支持用户手动录入、编辑、查看和删除标准字段及简单自定义字段；资料默认加密保存在本地，敏感字段需要确认，后续供文档解析和网页填写功能使用。”

## Overview

F001 为智能简历填写助手建立第一份可用的本地资料来源。用户可以在资料库中维护自己的身份、联系方式、教育、经历、技能和申请答案等资料，并在需要时增加简单的自定义字段。资料库只保存用户明确确认过的内容，向后续解析、匹配和填写功能提供稳定的字段语义。

本 Feature 只处理“资料的手动维护和本地生命周期”，不处理文档解析、OCR、网页识别、网页填写或模型推理；这些能力分别由后续 Feature 负责。

## User Scenarios & Testing

### User Story 1 - 手动维护基本资料 (Priority: P1)

用户打开资料库后，可以查看当前资料，录入或修改常用标准字段（例如姓名、联系方式和教育信息），保存后下次仍能使用。

**Why this priority**: 这是后续文档标准化、网页匹配和自动填写的最小可靠资料来源，也是用户第一次使用产品就能获得的直接价值。

**Independent Test**: 在没有文档解析和网页插件的情况下，创建一份包含姓名、邮箱和一条教育经历的资料，关闭并重新打开资料库，确认内容完整保留；修改其中一项后再次读取，确认只有该项发生变化。

**Acceptance Scenarios**:

1. **Given** 资料库为空，**When** 用户填写有效的姓名、邮箱和教育记录并保存，**Then** 资料库显示已保存的值、字段名称和最近更新时间。
2. **Given** 资料库已有一项已确认的字段，**When** 用户编辑并保存有效的新值，**Then** 新值替换旧值，其他字段和记录不变。
3. **Given** 用户输入不符合字段类型或格式的值，**When** 用户尝试保存，**Then** 系统指出具体错误且不改变此前已保存的有效值。
4. **Given** 用户取消编辑，**When** 返回资料库，**Then** 未保存的修改不会出现在资料中。

---

### User Story 2 - 管理重复经历和简单自定义字段 (Priority: P2)

用户可以维护多条教育、工作、实习或项目经历，并在标准字段不足时创建一个简单的自定义字段，明确指定它的类型和使用范围。

**Why this priority**: 个人经历通常是可重复的；不同招聘网站还会出现标准清单之外的字段。支持受控扩展可以覆盖常见资料，而不允许任意结构破坏共享语义。

**Independent Test**: 在已有基本资料的情况下，新增两条教育记录和一条项目记录，再创建一个“可接受城市”的枚举自定义字段；分别编辑、删除和重新读取，确认记录边界、类型和范围均保持正确。

**Acceptance Scenarios**:

1. **Given** 用户已有一条教育或经历记录，**When** 用户新增另一条记录并保存，**Then** 两条记录独立展示，编辑或删除其中一条不会改变另一条。
2. **Given** 用户准备创建一个自定义字段，**When** 用户选择名称、类型、值和使用范围并明确确认，**Then** 字段被加入资料库，并显示其类型、范围和敏感级别。
3. **Given** 自定义字段名称或标识与系统标准字段冲突，**When** 用户尝试保存，**Then** 系统拒绝创建并说明冲突，不修改现有字段定义。
4. **Given** 自定义字段类型为枚举、多值或布尔，**When** 用户输入不在允许集合内的值，**Then** 系统拒绝该值并保留字段的既有有效值。
5. **Given** 用户取消创建自定义字段或取消新增记录，**When** 返回资料库，**Then** 不产生新的永久字段或空记录。

---

### User Story 3 - 查看、导出和删除本地资料 (Priority: P2)

用户可以了解资料的来源和确认状态，主动导出自己的资料，或删除单项及全部资料；这些操作不需要登录云端服务。

**Why this priority**: 资料包含身份证件、联系方式和经历等高敏感内容。可见、可带走、可删除是用户信任本地优先产品的基本条件。

**Independent Test**: 使用一份包含普通字段、敏感字段和自定义字段的资料，逐项检查来源与确认状态，执行一次用户主动导出，再删除单项和全部资料；重新打开资料库后确认删除结果，并确认取消删除不会造成数据变化。

**Acceptance Scenarios**:

1. **Given** 资料库中有普通和敏感字段，**When** 用户查看字段详情，**Then** 系统显示字段来源、确认状态、敏感级别和更新时间，但不在普通运行日志中暴露值。
2. **Given** 用户主动选择导出，**When** 用户确认导出范围和文件位置，**Then** 系统生成包含所选资料的结构化文件，并明确提示文件由用户负责保管。
3. **Given** 用户选择删除一项或全部资料，**When** 用户在二次确认中确认，**Then** 选定资料被删除且不再出现在后续读取结果中。
4. **Given** 用户在删除确认或导出对话中取消，**When** 操作结束，**Then** 原资料保持不变。
5. **Given** 本地资料存储不可读或发生写入中断，**When** 用户打开或保存资料，**Then** 系统显示可理解的错误，不覆盖最近一次有效资料，并提供重试或人工恢复入口。

### Edge Cases

- 用户提交空白、全是空格或超出合理长度的值时，系统拒绝该值并说明原因。
- 同一标准字段只能有一个当前全局值；教育、工作、实习和项目等可重复实体允许多条记录，并保持稳定的记录标识。
- 同一字段同时存在全局、网站或本次申请范围时，资料库必须显示范围，不能静默合并成一个值。
- 自定义字段删除只删除该字段及其值，不删除其他标准字段；删除标准字段定义本身不允许由用户操作。
- 用户关闭资料库或进程在保存过程中退出时，下一次打开必须得到最近一次完整写入的资料，或明确报告恢复失败。
- 资料库没有任何值时，读取操作返回可区分的空状态，而不是错误或虚假默认值。
- 敏感字段或新建永久自定义字段的确认被拒绝时，候选值可以丢弃，但不得写入资料库。
- F001 不尝试处理文档解析失败、网页控件不可识别或模型不可用；这些情况由对应 Feature 显式报告。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 提供产品基线中定义的标准字段目录及稳定语义标识；标准字段不因某个网站或某次申请缺失而被删除或改名。
- **FR-002**: 用户 MUST 能够查看、手动新增、编辑和删除标准字段的值；标准字段目录本身不允许被用户删除。
- **FR-003**: 系统 MUST 支持个人身份、联系方式、教育、工作、实习、项目、技能、语言、证书、奖项、链接和常见申请答案等产品基线中的资料类别。
- **FR-004**: 系统 MUST 支持教育、工作、实习和项目等可重复记录；每条记录 MUST 可单独查看、编辑和删除，并保留稳定的记录标识。
- **FR-005**: 系统 MUST 对文本、日期、数字、布尔、枚举和多值等字段执行类型、格式、长度和允许值校验；校验失败 MUST 不得改变最近一次有效值。
- **FR-006**: 系统 MUST 区分“没有填写的字段”和“用户明确填写为空”的状态，不能用未确认的默认值代替空状态。
- **FR-007**: 用户 MUST 能够创建简单自定义字段，并为其指定用户可读名称、字段类型、一个或多个值、使用范围和可选的敏感级别及校验限制。
- **FR-008**: 新建自定义字段、修改自定义字段定义或把候选值永久写入资料库 MUST 经过用户明确确认；取消确认不得产生永久变更。
- **FR-009**: 自定义字段的标识和名称 MUST 不得覆盖或冒充标准字段；冲突时系统 MUST 拒绝创建并说明原因。
- **FR-010**: 每个资料值 MUST 记录来源类别（手动录入或后续导入流程）、确认状态、使用范围和最近更新时间；F001 产生的值来源为手动录入。
- **FR-011**: 系统 MUST 为产品基线中列出的高风险字段提供默认敏感标记和保存确认；本 Feature 不允许通过普通字段编辑流程绕过该确认。
- **FR-012**: 资料库主存储 MUST 默认只在本机保存个人资料，并使未经应用解密的静态文件无法读取明文；具体加密实现和密钥托管方式在计划阶段确定。
- **FR-013**: F001 的资料维护、查看、导出和删除流程 MUST 不向远程模型或其他云端服务发送个人资料；后续需要远程处理时必须由独立 Feature 的同意策略控制。
- **FR-014**: 系统 MUST 不把个人资料、敏感值、导出内容或 API Key 写入普通日志、调试输出、公开测试样例或版本库。
- **FR-015**: 资料写入 MUST 具备完整性保护：一次保存要么完整生效，要么保留最近一次有效资料；部分写入不得成为可见状态。
- **FR-016**: 用户 MUST 能够按选择范围主动导出本地资料的结构化副本；导出前必须显示范围并取得确认，导出后不得自动上传。网站配置导出由后续 Feature 负责。
- **FR-017**: 用户 MUST 能够在确认后删除单个字段值、单条重复记录、自定义字段或全部本地资料；删除和取消删除的结果必须可观察。
- **FR-018**: 资料库 MUST 提供清晰的空状态、校验失败、存储不可用、导出失败和删除失败反馈，并提供重试或人工处理入口。
- **FR-019**: F001 MUST 不执行网页读取、网页填写、页面导航、文件解析、OCR、模型调用或任何申请提交动作。
- **FR-020**: 资料结构 MUST 能被后续 Feature 通过 `packages/contracts/` 的共享契约读取；扩展和本地服务不得各自定义冲突的字段含义。

### Key Entities

- **Profile**：用户的一套可供申请使用的资料集合；首版默认只有一个本地用户和一套主资料，但结构应保留未来多套资料的区分能力。
- **Standard Field Definition**：系统预置的稳定字段语义、显示名称、字段类型和默认敏感级别；定义不随单个网站改变。
- **Custom Field Definition**：用户确认创建的字段名称、类型、范围、敏感级别和校验限制；不得与标准字段冲突。
- **Field Value**：某个标准或自定义字段在一个范围内的当前值，包含来源、确认状态、更新时间和必要的校验信息。
- **Repeatable Record**：教育、工作、实习或项目的一条独立经历，包含记录类型、字段值集合、排序信息和生命周期状态。
- **Scope**：资料值的使用范围，取 `global`（全局）、`website`（特定网站）或 `application`（单次申请）；F001 只维护范围，不执行网页匹配。`website` 是共享契约中的正式枚举值。
- **Export Request**：用户主动发起的导出范围和确认状态；它是一次性操作记录，不代表系统拥有上传权限。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 新用户在不阅读开发文档的情况下，可以在 5 分钟内完成姓名、联系方式和一条教育记录的首次保存，并在重新打开资料库后完整看到这些值。
- **SC-002**: 100% 的类型或格式无效输入都能在保存前被指出，且不会覆盖最近一次有效值；该结果由自动化验收场景覆盖。
- **SC-003**: 100% 的敏感字段写入、新建永久自定义字段和删除操作都能在记录变更前观察到明确的用户确认步骤。
- **SC-004**: 在关闭远程模型同意的情况下，资料库的新增、读取、编辑、导出和删除场景产生 0 次个人资料出站请求；通过网络拦截验收验证。
- **SC-005**: 对不超过 500 个字段值和 100 条重复记录的本地资料，打开资料和保存一次编辑的用户可感知等待时间在正常设备上均不超过 1 秒（95% 的验收运行）。
- **SC-006**: 资料库发生模拟的保存中断或存储读取错误时，100% 的验收运行都保留最近一次完整有效资料，或显示明确的不可恢复提示，不出现静默丢失。
- **SC-007**: 用户主动导出的文件只包含所选范围，且在未执行上传操作的情况下可被用户重新读取；删除确认后的资料在后续读取中 100% 不再出现。
- **SC-008**: F001 的自动化测试覆盖每个功能需求至少一个正向或负向场景，并且所有验收场景无需浏览器网站、远程模型或云端账户即可运行。

## Assumptions

- F001 面向单机、单用户的个人部署，不提供账户、多人协作或云端同步。
- 资料库的主要用户入口是产品已规划的资料库/设置页面；具体页面技术实现、进程通信方式和存储组件由 `plan.md` 决定。
- F000A 的共享字段与消息契约（PR #1，`docs/contracts-v0.1`，合并提交 `23b9d2b`）是 F001 的上游依赖；该稳定版本已可用，运行时代码必须直接复用它。
- 产品基线中的标准字段清单是本 Feature 的语义来源；标准字段并不意味着用户必须填写全部字段。
- F001 的“来源为手动录入”不排斥后续 F002/F003 追加文档来源、置信度和待确认候选，但 F001 不实现这些解析流程。
- 加密、密钥恢复和损坏数据恢复的具体方案必须在计划阶段选择，并以可测试的本地失败行为为准。
- 本 Feature 不改变产品级安全红线：不自动提交申请，不绕过验证码、OTP、签名、支付或反爬机制。

## Out of Scope

- PDF、Word、文本和图像型 PDF 的解析与 OCR（F002）。
- Agent 归类、语义标准化、文档候选合并和远程模型 Provider（F003 及后续 Feature）。
- 浏览器扩展的页面扫描、字段匹配、自动填写、冲突提示和撤销（F004 及后续 Feature）。
- 复杂自定义控件、附件、富文本、批量投递、自动提交和多用户服务器。
- 网站标签映射和网站配置的保存、导出与共享（F012）。
- Agent 长期对话、自动训练或未经用户确认的网站规则学习。
