# Feature Specification: 资料标准化与人工纠正

**Feature Branch**: `feat/F003-standardization`
**Created**: 2026-09-05
**Status**: Specifying
**Input**: F002 文档解析结果、F001 本地资料库和产品基线中的标准字段

## Overview

F003 将 F002 产生的结构化字段候选整理为可写入 F001 的标准化资料。流程先使用本地确定性规则完成值的清理、类型转换和格式校验，再对 F002 已提供的教育/经历字段按来源位置进行有限的记录归类。系统把标准化结果、来源、置信度、校验问题、已有资料冲突和重复记录建议展示给用户；用户逐项接受、修改、跳过或拒绝后，才通过 F001 的版本校验和确认写入流程保存。

F003 不改变浏览器页面扫描、网页填写、自动提交或远程文件上传边界。远程模型 Provider 不在本 Feature 中启用；规则无法判断的内容必须保留为待人工处理，并明确说明原因。

## User Scenarios & Testing

### User Story 1 - 标准字段清理与归一化（Priority: P1）

作为用户，我希望导入资料中的常见格式被统一，例如日期、电话、邮箱、空白和学历名称，以便后续资料读取和网页匹配使用稳定的值。

**Independent Test**: 使用脱敏的 F002 候选和片段，验证规则能够生成标准字段候选、保留原始证据、标出变更和无法判断的项目，并且预览不改变资料库。

**Acceptance Scenarios**:

1. **Given** 候选含有多余空白、中文日期、常见电话或邮箱写法，**When** 开始标准化，**Then** 系统返回规范值、原始值、转换说明和来源位置。
2. **Given** 候选无法通过字段类型或格式校验，**When** 标准化完成，**Then** 候选被标记为需要人工纠正并带有可理解的问题，不生成伪造值。
3. **Given** 标准化任务正在预览，**When** 用户尚未确认，**Then** F001 的资料内容、字段定义和版本号保持不变。
4. **Given** 同一字段从多个片段产生不同候选，**When** 系统完成归并，**Then** 系统保留每个来源并给出冲突列表，不静默选择一个值。

### User Story 2 - 重复经历归类与资料合并（Priority: P1）

作为用户，我希望 F002 已识别的教育/经历字段被整理为可重复记录，并与已有记录区分新增、可能重复和冲突，以便我可以逐条检查。项目、未知类型和复杂跨段归类保留到后续解析能力完善后处理。

**Independent Test**: 使用包含多条教育和经历片段的脱敏文档及已有资料，验证记录类型、字段分组、排序建议、重复提示和冲突提示均可追踪，且未确认记录不会写入。

**Acceptance Scenarios**:

1. **Given** F002 片段包含可映射的教育/经历字段及时间，**When** 标准化完成，**Then** 系统生成带 `record_type` 的重复记录候选，并保留每个字段的来源和置信度；F002 未提供的项目和未知类型不会被伪造。
2. **Given** 候选记录与已有记录具有相同组织/学校和重叠时间，**When** 进行重复预览，**Then** 系统标记可能重复并同时展示两边内容，等待用户选择接受为新记录或拒绝；首版不自动合并已有记录。
3. **Given** 记录缺少足以判断类型或身份的关键字段，**When** 进行归类，**Then** 系统保留为未归类候选并提供人工选择入口，不把它写成错误的记录类型。
4. **Given** 候选可能与已有记录重复，**When** 用户查看预览，**Then** 系统展示字段级来源、冲突值和重复依据；用户未确认前不修改已有记录。

### User Story 3 - 人工纠正与确认写入（Priority: P1）

作为用户，我希望在一个可取消的审阅流程中修改标准化结果，并确认哪些字段或记录进入资料库。

**Independent Test**: 对普通字段、敏感字段、新增记录、已有值冲突和无效修改分别执行接受、修改、跳过、拒绝和取消，验证只有明确确认且通过校验的结果写入。

**Acceptance Scenarios**:

1. **Given** 用户打开标准化预览，**When** 修改候选值或记录类型并确认，**Then** 修改后的值重新执行字段、记录和敏感级别校验，成功后才可提交。
2. **Given** 候选是敏感字段、长文本或新增重复记录，**When** 用户未完成明确确认，**Then** 系统不得写入资料库。
3. **Given** 用户选择跳过、拒绝或取消，**When** 流程结束，**Then** 未确认结果不会出现在 F001 读取结果中，资料版本不增加。
4. **Given** 预览后资料版本已改变，**When** 用户提交确认，**Then** 系统拒绝过期写入，保留当前资料并要求重新生成或重新审阅。
5. **Given** 用户重复提交同一确认请求，**When** 请求标识相同，**Then** 系统返回同一结果，不重复创建记录或覆盖新资料。

### User Story 4 - 失败处理与隐私边界（Priority: P1）

作为用户，我希望标准化失败、规则无法判断或本地存储不可用时能清楚知道下一步，并确认个人资料没有未经同意离开本机。

**Independent Test**: 使用空候选、冲突候选、无效字段、过期任务、存储错误和远程同意关闭的场景，验证错误可理解、资料保持完整、普通日志不包含个人资料且出站请求为零。

**Acceptance Scenarios**:

1. **Given** 标准化任务没有可处理候选或所有候选都无法归类，**When** 任务结束，**Then** 系统返回空结果或人工处理提示，而不是成功写入。
2. **Given** 规则校验发现日期范围、枚举、必需字段或重复记录冲突，**When** 用户查看预览，**Then** 问题与影响范围显示在对应候选上，并允许纠正或拒绝。
3. **Given** 本地资料读取或写入失败，**When** 用户确认结果，**Then** 系统报告失败且保留最近一次完整资料，不返回成功状态。
4. **Given** 用户没有明确同意远程模型，**When** 执行标准化，**Then** 原文、候选值、证据和资料不会发送到远程服务，并返回 `model_used=false`、`remote_data_sent=false`。
5. **Given** 任务取消、过期或清理失败，**When** 后续请求到达，**Then** 任务不能继续写入，清理结果和人工处理建议可观察。

## Functional Requirements

- **FR-001**: 系统必须只接受 F002 任务产生的结构化片段或候选作为 F003 输入；F003 不直接读取网页、远程文件或用户目录中的任意文件。
- **FR-002**: 系统必须为每个标准化结果保留原始值、规范值、标准字段标识或记录类型、来源位置、证据、置信度、转换说明和警告。
- **FR-003**: 系统必须使用确定性规则处理空白、大小写、常见日期、电话、邮箱、URL、数字和枚举别名；规则无法安全判断时必须保留人工处理状态。
- **FR-004**: 系统必须在标准化预览阶段执行 F001 的字段类型、格式、范围、敏感级别和空值语义校验；校验失败不得产生可写入的已确认值。
- **FR-005**: 系统必须把 F002 已提供且可识别的教育/经历片段归类为可重复记录候选；每条记录必须带稳定的任务内标识、记录类型建议、字段集合、来源和置信度。项目、未知类型在输入未提供时不得猜造。
- **FR-006**: 系统必须支持同一字段的多候选保留，并展示候选之间的冲突；不得仅因置信度较高而静默覆盖已有值或丢弃其他来源。
- **FR-007**: 系统必须对候选与已有字段值、已有重复记录进行新增、可能重复、冲突和无需变更的分类，并说明分类依据。
- **FR-008**: 用户必须能够对字段候选和记录候选逐项接受、修改、跳过或拒绝；修改后必须重新校验。首版只提供重复建议，不自动合并已有记录。
- **FR-009**: 新增记录、合并记录、敏感字段、长文本和任何冲突覆盖必须要求用户明确确认；未确认结果不得进入 F001。
- **FR-010**: 确认写入必须复用 F001 的 `profile_id`、`expected_profile_version`、幂等请求和原子保存语义；版本过期时不得覆盖最新资料。
- **FR-011**: 取消、拒绝、过期和失败的标准化任务必须使未确认结果失效，不能由后台或重复请求继续写入。
- **FR-012**: F003 默认不得调用远程模型；在没有明确同意时，任何远程调用都必须被阻止。即使未来接入 Provider，也只能发送完成当前任务所需的最少脱敏内容，并返回出站和同意状态。
- **FR-013**: 原始证据、候选值、用户纠正和任务中间状态只能在短生命周期任务中保存；普通日志、测试样例和 Git 不得包含真实个人资料或完整文档内容。
- **FR-014**: 扩展页面必须展示规范值、原始证据、来源、置信度、警告、已有值和变更说明，并提供键盘可达的确认、修改、跳过、拒绝和取消操作。
- **FR-015**: F003 不得执行网页扫描、网页填写、页面导航、申请提交、验证码/OTP/签名/支付/反爬处理或自动创建长期记忆。

## Key Entities

- **NormalizationTask**：关联 F002 任务和 F001 资料版本的短生命周期任务，保存标准化候选、警告、同意状态和生命周期。
- **NormalizedCandidate**：字段或重复记录的规范化候选，包含原始值、规范值、来源、置信度、校验结果、冲突分类和确认要求。
- **RecordCandidate**：教育或经历记录候选，包含任务内记录标识、类型建议、字段候选、重复匹配依据和已有记录摘要。
- **NormalizationDecision**：用户对候选执行接受、修改、跳过或拒绝的决定，带明确确认和可选纠正说明。
- **NormalizationIssue**：与字段、记录或任务关联的可读问题，包含错误/警告级别、原因和建议人工动作。

## Data Flow

```text
F002 ImportTask
  → ParsedSegment / ProfileImportCandidate
  → 本地规则清理、类型转换、字段与记录归类
  → 字段/记录候选 + 来源 + 置信度 + 校验问题
  → 与 F001 当前资料比较：新增 / 可能重复 / 冲突 / 无变化
  → Options 页面逐项纠正和确认
  → expected_profile_version 校验
  → F001 ProfileService 原子写入
```

预览阶段只产生任务内状态，不改变 F001 快照。确认阶段只提交用户明确接受或修改后的结果；拒绝、跳过和取消不产生资料变更。

## Success Criteria

- **SC-001**: 脱敏测试集中的明确姓名、邮箱、电话、日期和常见学历值，至少 95% 能得到正确的规范值或明确的人工处理提示。
- **SC-002**: 每个标准化候选都能回溯到至少一个文档位置或 F002 候选标识；无法回溯的候选不会进入可确认状态。
- **SC-003**: 对包含多条教育和经历的脱敏样例，所有生成的记录候选都带记录类型、字段来源、置信度和重复/冲突结论；未确认记录为零条持久化结果。
- **SC-004**: 预览、纠正、取消和拒绝场景中，F001 资料快照及版本保持不变；确认场景中只有用户选定的字段和记录写入。
- **SC-005**: 资料版本并发变化时，100% 的确认请求被拒绝或要求重新审阅，不覆盖较新的资料。
- **SC-006**: 远程同意关闭的所有自动化验收运行中，个人资料出站请求为 0；响应明确报告模型未使用和未出站。
- **SC-007**: 对不合法值、无法归类、重复冲突、任务过期和存储失败，系统均返回稳定错误/警告类别和人工处理入口，不产生静默成功。

## Assumptions

- F001 的标准字段目录、重复记录模型、加密存储、版本控制、幂等和确认写入作为现有依赖复用，不在 F003 重写。
- F002 的任务对象在标准化任务创建时仍可访问；F003 不建立永久文档库。若 F002 任务已过期，系统要求重新解析文件。
- 首版只支持规则可解释的常见中文/英文简历格式；复杂版式、手写内容、跨页语义重建和多语言高质量归类保留人工处理。
- `SourceKind.AGENT` 可以作为结构化候选来源标记，但没有远程 Provider 时不产生模型调用；规则和用户纠正分别使用已有的 `rule` 与 `user_correction` 来源。
- 用户确认后的标准化结果属于 F001 普通资料，不构成 Agent 长期记忆或自动学习规则。

## Out of Scope

- 浏览器页面字段扫描、网页填写、网页导航和填写撤销（F004 及后续 Feature）。
- 远程模型 Provider、模型训练、长期记忆、自动学习网站映射和云端资料同步。
- `.doc`、复杂网页、手写 OCR、复杂表格跨页还原和所有语言的完全准确归类。
- 自动提交招聘申请、验证码、OTP、签名、支付、反爬或批量投递。
- 多用户账户、服务端数据库和跨设备同步。
