# Feature Specification: 文档资料解析与确认导入

**Feature Branch**: `feat/F002-document-parsing`  
**Created**: 2026-09-05  
**Status**: Draft  
**Input**: PDF、DOCX、图像型 PDF 的本地解析，展示候选字段、来源和置信度，用户确认后写入 F001 资料库。

## Overview

F002 为 F001 本地资料库增加文档导入入口。用户选择本地 PDF 或 DOCX 文件后，系统提取文本；对于缺少可读文本层的 PDF，系统使用本地 OCR。解析结果只能作为带证据、来源和置信度的待确认候选展示，不能直接覆盖已有资料或永久保存。用户逐项确认、修改或拒绝后，确认结果才通过 F001 已有的版本校验和资料写入流程保存。

## User Scenarios & Testing

### User Story 1 - 导入可读 PDF 或 DOCX（Priority: P1）

作为用户，我希望选择一份本地 PDF 或 DOCX 简历并看到解析出的候选资料，以便检查导入结果而不必重新手工录入全部内容。

**Independent Test**: 使用脱敏的文本型 PDF 和 DOCX，确认系统能够提取正文/表格文本，返回候选字段、来源位置、证据、置信度和警告，且资料库未发生变化。

**Acceptance Scenarios**:

1. **Given** 用户选择受支持且可读取的 PDF，**When** 开始预览，**Then** 系统返回文档标识、文件元数据、候选字段和每个候选的来源位置。
2. **Given** 用户选择受支持且可读取的 DOCX，**When** 开始预览，**Then** 系统提取段落和表格中的可读文本并生成待确认候选。
3. **Given** 文件成功解析，**When** 预览响应返回，**Then** 所有候选都标记为需要用户确认，且资料库内容、版本号和已确认字段不改变。
4. **Given** 文件只包含暂时无法归类的文本，**When** 预览完成，**Then** 系统保留可追踪的警告或未识别说明，不伪造字段值。

### User Story 2 - 处理图像型 PDF（Priority: P1）

作为用户，我希望图像型 PDF 能够在本地进行 OCR，以便导入扫描件中的姓名、联系方式和经历信息。

**Independent Test**: 使用脱敏的图像型 PDF，确认系统识别需要 OCR、完成本地 OCR 或报告清晰失败，并在两种情况下都不写入未确认资料。

**Acceptance Scenarios**:

1. **Given** PDF 没有足够的文本层，**When** 用户选择自动处理，**Then** 系统进入本地 OCR 流程并在结果中说明使用了 OCR。
2. **Given** OCR 成功识别部分内容，**When** 预览完成，**Then** 候选包含页码/区域等来源信息、证据文本、置信度和必要警告。
3. **Given** OCR 引擎不可用、文件无法渲染或识别失败，**When** 处理结束，**Then** 系统返回可理解的失败原因和人工录入入口，不生成虚假的候选。
4. **Given** 用户选择不使用 OCR，**When** 文件没有可用文本层，**Then** 系统报告无法解析文本，并保持资料库不变。

### User Story 3 - 审核并确认导入结果（Priority: P1）

作为用户，我希望逐项接受、修改或拒绝解析候选，以便只有我确认过的内容进入资料库。

**Independent Test**: 对包含普通字段、敏感字段和已有资料冲突的预览结果逐项作出决定，确认只有接受或修改后的候选写入，拒绝和未处理候选不写入。重复经历的语义归类和 Record 写入留给后续 Feature。

**Acceptance Scenarios**:

1. **Given** 预览中存在候选，**When** 用户接受某候选，**Then** 系统在写入前再次执行字段类型、格式、敏感级别和范围校验。
2. **Given** 用户修改某候选，**When** 提交修改并确认，**Then** 系统保存修改后的值，并保留来源为文档导入且记录用户确认。
3. **Given** 候选对应敏感字段或与已有资料冲突，**When** 用户查看预览，**Then** 系统同时展示候选值、已有值/冲突说明、来源、置信度和警告，不能静默覆盖。
4. **Given** 用户拒绝或取消导入，**When** 操作结束，**Then** 不写入资料库，不增加资料版本，不保留未确认候选为永久资料。
5. **Given** 资料版本在预览后发生变化，**When** 用户确认写入，**Then** 系统拒绝过期写入并要求重新读取、重新审核。

### User Story 4 - 失败、取消和隐私边界（Priority: P1）

作为用户，我希望文件问题、解析问题和隐私设置都能明确反馈，以便我知道资料是否被保存以及是否有数据离开本机。

**Independent Test**: 使用不支持、损坏、加密、超大和超时文件，并分别测试本地默认模式和未授权远程模式，确认错误可理解、资料不被污染且没有未授权出站请求。

**Acceptance Scenarios**:

1. **Given** 文件扩展名或媒体类型不在 F002 支持范围内，**When** 用户选择该文件，**Then** 系统在开始解析前拒绝并说明支持范围。
2. **Given** 文件损坏、受密码保护、超过大小/页数限制或处理超时，**When** 解析失败，**Then** 系统返回稳定错误类别、人工处理建议和资料不变的结果。
3. **Given** 用户未明确同意远程模型，**When** 执行预览，**Then** 文档内容、OCR 文本和候选值不发送到远程服务。
4. **Given** 用户明确同意远程模型且当前流程确实需要语义辅助，**When** 发生远程调用，**Then** 系统只发送完成当前任务所需的最少内容，并记录是否使用模型、是否出站和同意状态。
5. **Given** 解析任务结束或取消，**When** 清理临时资源，**Then** 原始文档和中间文本不会进入普通日志、Git 或 F001 永久资料库。

## Functional Requirements

- **FR-001**: 系统必须只接受用户主动选择的本地文件作为导入输入。
- **FR-002**: F002 首版必须支持 PDF 和 DOCX；`.doc`、远程文件、网页地址和未知媒体类型必须明确拒绝。
- **FR-003**: 系统必须在解析前校验文件名、媒体类型、文件大小、可读性和内容哈希，并为本次任务生成不透明文档标识。
- **FR-004**: 文本型 PDF 必须提取可追踪的文本片段和页码/区域位置；DOCX 必须覆盖普通段落和表格中的文本。
- **FR-005**: 对缺少可用文本层的 PDF，系统必须支持本地 OCR；OCR 是否使用必须可在结果中观察到。
- **FR-006**: 解析器输出必须与字段归类和资料写入解耦，只产生原文片段、位置、证据和解析警告。
- **FR-007**: 候选必须使用共享契约中的字段标识和类型，并包含候选 ID、值、来源、位置、证据、置信度、确认要求和警告。
- **FR-008**: F002 产生的候选必须始终处于待确认状态；候选预览不能改变 F001 资料、版本号或字段定义。
- **FR-009**: 用户必须可以逐项接受、修改或拒绝候选；修改后的值必须重新经过 F001 的类型、格式、范围和敏感字段校验。
- **FR-010**: 系统必须展示来源文档、页码/区域或段落位置、证据文本、置信度和疑问；无法定位来源的候选必须带警告或被标为不可确认。
- **FR-011**: 已有资料冲突时，系统必须同时展示已有值和候选值，等待用户决定，禁止静默覆盖。
- **FR-012**: 用户取消、拒绝或关闭确认流程时，不得写入未确认候选，不得增加资料版本，不得伪造成功结果。
- **FR-013**: 确认写入必须复用 F001 的用户确认、`expected_profile_version`、幂等和错误语义；过期版本必须返回可操作的冲突结果。
- **FR-014**: 系统必须对不支持、损坏、加密、超文件大小/50 页、超时、空文档、OCR 不可用和无候选情况返回可理解的错误或警告，并提供人工处理入口。
- **FR-015**: 远程模型调用默认关闭；未记录用户同意时，系统不得发送原文、OCR 文本、候选值或完整资料。
- **FR-016**: F002 不启用远程模型 Provider；即使请求携带远程同意，当前解析入口也必须拒绝该模式或保持本地处理，并记录 `model_used=false`、`remote_data_sent=false`。后续 Feature 若接入 Provider，必须先扩展契约、最小数据范围和审计测试。
- **FR-017**: 原始文件、中间文本、OCR 结果和未确认候选只能在当前任务生命周期内保存；任务结束后应清理临时资源，清理失败必须可观察。
- **FR-018**: 普通日志、测试夹具和 Git 历史不得包含真实个人资料、完整文档内容、密钥、完整导出内容或不必要的绝对隐私路径。
- **FR-019**: F002 不得新增自动提交、网页导航、验证码/OTP/签名/支付处理、复杂网页解析、多用户云端同步或长期记忆能力。
- **FR-020**: F002 必须优先复用 v0.1 中的 `DocumentRef`、`ProfileImportPreview*`、`ImportDecision` 和 F001 资料写入契约；若发现契约不足，必须先记录契约变更再实现。

## Key Entities

- **DocumentRef**：本次导入的文档身份和元数据，包括文档 ID、显示文件名、媒体类型、大小和哈希。
- **ParsedSegment**：从文档或 OCR 结果得到的文本片段、页码/区域/段落位置和解析警告；不等于资料字段。
- **ProfileImportCandidate**：待确认的标准字段候选，包含值、来源、证据、置信度和警告。
- **ImportDecision**：用户对候选作出的接受、修改或拒绝决定。
- **ImportTask**：贯穿文件校验、解析、预览和确认的短生命周期任务，不作为长期记忆。
- **ConfirmationState**：候选的待确认、已接受、已修改、已拒绝或已取消状态；只有已确认结果可以进入 F001。

## Error Handling and Privacy Boundaries

- 错误响应不得回显原文、敏感字段值、密钥、完整导出内容或完整本地路径。
- 文件无法读取时保留资料库原快照；解析失败不能触发资料写入。
- 任务超时或用户取消后，后续确认请求必须失效或被拒绝，不能在后台继续写入。
- 任何出站请求必须有明确同意记录；没有同意时应使用本地规则或返回待人工处理。
- 临时文件和中间结果不得被当作 F001 已确认资料读取。

## Success Criteria

- **SC-001**: 对脱敏测试集中的受支持文本型 PDF 和 DOCX，至少 95% 的预期可见字段能够返回可定位来源的候选或明确的未识别说明。
- **SC-002**: 对脱敏图像型 PDF，系统能够明确区分“使用 OCR 后得到候选”“OCR 失败”和“用户选择不使用 OCR”三种结果。
- **SC-003**: 预览阶段资料库内容、已确认字段和资料版本保持不变；未确认候选不会出现在普通资料读取结果中。
- **SC-004**: 用户可以对每个候选作出接受、修改或拒绝决定；所有写入结果都能关联到原始文档和来源位置。
- **SC-005**: 在未同意远程模型的测试场景中，出站请求数量为 0；在同意场景中，响应明确记录出站状态和同意状态。
- **SC-006**: 对不支持、损坏、加密、超限和 OCR 失败文件，系统不会污染资料库，并返回可操作的错误或人工处理提示。
- **SC-007**: 在资料版本发生变化的并发场景中，确认写入不会覆盖新版本，且用户能得到重新审核提示。

## Assumptions

- F001 的本地加密存储、ProfileService、版本控制和确认写入流程作为已完成依赖，不在 F002 中重写。
- F002 首版按常见简历文档处理，不承诺复杂版式完全还原、手写识别、表格跨页语义重建或所有语言的高质量识别。
- 原始文件默认只作为当前任务输入，不自动复制到长期资料库；是否由用户主动保留原文件属于后续产品能力。
- 文档大小、页数、处理时长和 OCR 资源上限在计划阶段根据本地验证确定，但必须有明确上限和错误语义。
- 规则可以处理明确格式字段；经历归类、复杂语义和不确定字段必须保留人工确认。
- F002 不实现远程模型调用；远程 Provider 的同意、最小数据发送和审计留给后续模型能力 Feature。
- F002 首版不把解析文本自动重建为教育/工作/项目重复记录；这类经历归类和 Record 写入属于 F003。
- 共享契约中暂存的 `.doc` 媒体类型不代表 F002 首版承诺实现；首版支持范围以本规格 FR-002 为准。

## Out of Scope

- `.doc` 文件的完整支持；
- 远程文件 URL、网盘、邮箱或招聘网站文档抓取；
- 复杂网页解析和浏览器当前页面识别；
- 直接自动写入或覆盖已有资料；
- 自动提交招聘申请、点击下一步、验证码、OTP、签名、支付或反爬；
- 生产级多用户服务、云端同步和长期记忆；
- 复杂版式完全还原、手写识别、表格跨页语义重建和所有语言的高精度保证；
- 教育/工作/项目经历的语义归类和重复记录自动创建；
- 在 F002 中提前实现 F003 的完整 Agent 归类、跨字段纠错和长期标准化系统。
